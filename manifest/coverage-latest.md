Milestone: **M14.C-g** — fix flaky "double free or corruption (!prev)"
glibc abort seen under `--coverage` in `test_httpd_c.lua` /
`test_http_c.lua`. Root cause was in `src/net/http.c`
`check_multi_info()`: it called `fan_coro_wake` (which synchronously
`lua_resume`s the parked coroutine) **before** clearing `r->easy` and
`curl_easy_cleanup`-ing the handle. If the resumed Lua code either
dropped the last reference to the parked ctx userdata or ran
`collectgarbage()` — both easy to trigger in the loopback in-process
`httpd_c` tests — `l_req_gc` fired mid-wake and called
`curl_easy_cleanup(r->easy)`. Control then returned to
`check_multi_info`'s loop body which called `curl_easy_cleanup(easy)`
again on the same pointer, corrupting glibc's malloc arena.

Fix (`check_multi_info` only): free curl-owned resources (headers
list, body copy, easy handle) and `NULL` the `r->easy` pointer
**before** the `fan_coro_wake` call. All response bytes the caller
needs are already on the coroutine's Lua stack by that point, so
tearing down the C side early is safe and closes the double-cleanup
window. `l_req_gc` remains the safety net for coroutines that die
before their transfer completes; it only runs when `r->easy != NULL`.

Diagnostic infrastructure (kept, coverage builds only): `http.c`
grew a `fan_curl_cleanup(easy, site)` wrapper (macro
`CURL_EASY_CLEANUP`) that records every cleanup call in a 128-slot
ring buffer with an execinfo backtrace, marks pointers as stale when
`curl_easy_init` reissues them, and `abort()`s with a formatted
report **before** glibc's arena check fires. Enabled by
`-DFAN_HTTP_C_TRACE_CLEANUP=1` (auto-added by CMake when
`FAN_COVERAGE=ON`); zero cost otherwise. This is what caught the
bug and will catch any regression. Also kept:
`-fprofile-update=atomic` (thread-safe gcov counter updates —
libcurl's `--enable-threaded-resolver` briefly runs a resolver
thread on every request), and `tests/Dockerfile` picks up
`gdb strace ltrace valgrind` so future debug sessions do not need
apt-get. Three-mode gate: normal 443/443, --asan 443/443 with 0
LeakSanitizer reports, --coverage 443/443 C 85.1% Lua 91.06%
across three consecutive full-suite runs (zero flakes).

**C side** (`src/net/httpd.c`):
- `req:is_websocket_upgrade()` — header predicate (`Upgrade:
  websocket`, `Connection: upgrade`, `Sec-WebSocket-Key`,
  `Sec-WebSocket-Version: 13`), no I/O.
- `req:websocket_accept()` — RFC 6455 handshake. OpenSSL SHA1+base64
  builds the `Sec-WebSocket-Accept` digest (GUID
  `258EAFA5-E914-47DA-95CA-C5AB0DC85B11`); v1's Lua backend
  previously used a typo `…B29`, corrected here for both backends.
- Bufferevent hijack: `evhttp_request_own(r->ev)` +
  `evhttp_connection_set_closecb(evcon, NULL, NULL)` +
  `evhttp_connection_set_timeout(evcon, 0)` detach evhttp from the
  bev, `bufferevent_write` queues the 101 head, then
  `fan_tcp_adopt_bev_with_evcon` transfers ownership of both the
  bev and the enclosing `evhttp_connection` (plus the owned
  request) into a fan.tcp conn. The conn's `:close` / `__gc` calls
  `evhttp_connection_free(evcon)` first (releases the bev) and
  then `evhttp_request_free(req)` — this order avoids the
  libevent bufferevent refcnt assertion that a direct
  `bufferevent_free` would trip.
- `permessage-deflate` is negotiated symmetrically with the Lua
  backend: any client offer that mentions the extension yields
  `Sec-WebSocket-Extensions: permessage-deflate;
  server_no_context_takeover; client_no_context_takeover`.

**Lua side** (`lua/fan/httpd.lua`, `lua/fan/websocket.lua`):
