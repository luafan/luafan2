Milestone: **M18** — `fan.udp` gains the callback-based async API
that restores v1 `fan.udpd` semantics on top of libevent's raw
EV_READ / EV_WRITE watchers.  Two userdatas
(`fan.udp.async_sock` + `fan.udp.dest`), one new native entry
(`fan.udp.new_async{...}`), and two constructors for destination
objects (`make_dest` / `make_dests`).  The socket handle exposes
`send` / `send_req` / `getPort` / `rebind` / `close`; the dest
exposes `getHost` / `getIP` / `getPort`.  `require("fan.udpd")`
gives the v1 aliases `.new` / `.make_dest` / `.make_dests`.

The read path drains every pending datagram inside one callback tick
(recvfrom until EAGAIN) so a hot receiver does not thrash the
scheduler.  Each datagram spins up a fresh coroutine for
`onread(self, data, dest)` — same dispatch shape as fan.tcp async
callbacks, exactly-once close semantics inherited from the shared
`self_ref` release pattern.

`onsendready` fires once per explicit `sock:send_req()` — the write
watcher is a one-shot re-armed on demand rather than a continuously
firing edge trigger, matching v1's pacing contract.

Same two v1 fields rejected as in M17: `worker` (v2 has no
in-process worker event bases) and `callback_self_first` (v2
callbacks always self-first).  A third v1 feature, `evdns` on
`make_dest` / `make_dests`, is accepted for API parity but currently
ignored — v2 falls back to synchronous `getaddrinfo(3)`.  Async DNS
in `make_dest` is a self-contained follow-up documented in
manifest/udp.md.

Previous milestone: **M16.3** — `fan.json` regains two v1-era presence predicates:
`json.is_nonempty_string(v)` and `json.is_present(v)`.  Both cover the
common "validate a decoded body field" pattern in HTTP handlers.

`is_present` is particularly useful because v2 always decodes JSON
`null` to the `json.null` sentinel (never to Lua nil), so `body.field
== nil` cannot distinguish "absent key" from "explicit null".
`is_present` returns false for both, true for anything else — including
`""`, `0`, `false`, `{}`.

The v1 `json.enable_null(bool)` toggle is intentionally NOT restored:
v2's always-sentinel behaviour is safer (never drops keys on
encode round-trip) and adding a mode toggle would double the surface
area of every downstream test.  Callers that used `enable_null(false)`
to get Lua-nil for JSON null should rewrite `if v == nil` as `if not
json.is_present(v)`.

C: +25 lines in `src/codec/json.c` (two new `l_is_nonempty_string` /
`l_is_present` static functions + two registrations).  Both are covered
by three new tests in `test_json.lua` (17 → 20 tests total).  C
coverage held at 85.0%, Lua coverage held at 90.36% (new C code and
its tests are proportional).

Previous milestone: **M16.2** — `fan.orm` regains v1-era active-record row
objects.  Rows returned by `Model.insert` / `find_by` / `list` now
carry a metatable with three methods:

  `row:update([override])`  — zero-arg auto-diff (only UPDATE the
      columns whose current value differs from the load-time snapshot);
      one-arg mode UPDATEs exactly the given columns.  Returns
      rows_affected (0 when nothing changed and no SQL is issued).
      After a successful call the baseline snapshot is refreshed so
      successive `:update()` calls diff against the new state.
  `row:delete()`            — DELETE + setmetatable(self, nil) so the
      detached row can no longer accidentally issue SQL.
  `row:remove()`            — v1-era alias of `:delete()`.

Snapshot storage lives in a weak-key table attached to the model's row
metatable (`row_mt.__attr_map[row]`), keeping the row's own key space
free of internal fields (unlike v1's `r["^attr"]` string-key convention).

Breaking change: `Model.insert{...}` now returns a live row object
instead of the raw integer id (v1 shape).  Legacy code that captured
`local id = X.insert{...}` needs one token: `local u = X.insert{...};
local id = u.id`.  Three call sites in the test suite were updated
accordingly (test_orm, test_orm_mariadb, test_integration).  The
class-level `Model.update(id, fields)` / `Model.delete(id)` helpers
are unchanged.

Escape hatch: `Model.list{raw = true}` and `Model.raw_query(sql, ...)`
return plain maps (no metatable) for cheap read-only bulk access.

2. `tests/lua/framework/coverage.lua` learned `LUAFAN_LUACOV_CONFIG`
   env-driven config bootstrap: when a child process (e.g. the
   webase server that `test_webase.lua` spawns via `fan.popen`)
   chdirs before exec, luacov's default `.luacov` lookup fails and
   silently falls back to defaults, writing stats to `CWD/luacov.
   stats.out` — invisible to the aggregator. The env var points at
   an absolute path; the hook `dofile`s it, rewrites the (relative)

3. `test_webase.lua` sets `LUAFAN_LUACOV_CONFIG=$ROOT/.luacov` in the
